# 设计一致性复核：阶段 0 与阶段 1 入口

## 结论

阶段 0 的实现与设计说明的核心方向一致：原文按内容寻址、保留原始字符跨度、追加式校验、决策日志纳入同一回溯体系；阶段 0 没有生成历史解释。没有发现静默合并、残余裁决或置信度自增路径。阶段 0 的验收结论仍成立。

存在以下明确的实现差异与范围限制，进入阶段 1 时必须显式保留，不能把它们当作已解决：

1. **`source_id` 的粒度**：当前 `source_id` 是完整文本对象的 SHA-256；每个行单元另有 `content_hash` 与位置绑定的 `unit_id`。设计说明的 Agent 1 示例把每个最小单元称为 `source_id`。现有 `(source_id, char_range)` 能唯一回到原文位置，且重复句不会因 `unit_id` 重复而混淆，但字段命名与“每单元一个 source_id”的字面约定不同。阶段 1 沿用现存 ID，不改写阶段 0 已建立的内容寻址。
2. **切分粒度**：当前按输入换行切分，而非句子/子句切分。这是机械且可复现的阶段 0 选择，不包含训诂判断；KJV 诗节一行可能含多个句子，所以不能把“行单元”说成文献学最小单元。
3. **语料语言**：测试语料是 KJV 英文译文，不是希伯来文底本。它可支持坐标、结构边界与译文词面回溯，不能独立验证希伯来词形或神名差异。创世记的分层候选因此必须标为待审阅提案，不能声称由程序从希伯来语自动检测得出。
4. **J/P/D 适用范围**：启动说明要求检验 J/P/D 争议，但当前语料只有《创世记》1–3 章。Steven L. McKenzie 的 SBL/Bible Odyssey 综述把 D 说明为 Deuteronomy（《申命记》），并记载 Deuteronomy/Joshua 后来被从 Genesis–Numbers 的文献假说范围中分出；因此不能把 D 指派给当前《创世记》文本。当前阶段只可检验 P 与 J?/非 J 多来源路径是否并存；若要检验 J/P/D 三者，需另纳入《申命记》语料。
5. **尚未进入的系统模块**：`Residue` 表、残余比例守护、分支治理、还原提议 schema、事实类型拒写、三条健康度趋势和完整治理调度器尚未实现。它们不属于阶段 0 的交付；阶段 1 也不会借机把它们标为已验收。

## 阶段 1 的审慎执行方式

外部学术材料支持把两种不同路径并列作为**待审阅候选**，但不授权系统给出唯一结论或数值置信度：

- Steven L. McKenzie 的综述将传统划分描述为 Gen 1:1–2:3 的 P 与 Gen 2:4b–3:24 的 J?，并把 Gen 2:4a 视作连接句；同文指出 J 是否作为独立来源存在仍有学界分歧，P 与 D 的独特性则仍被普遍承认。来源：[Bible Odyssey：What Is Source Criticism?](https://www.bibleodyssey.org/articles/what-is-source-criticism/)
- Marc Zvi Brettler 对创世记两段创世叙事的神名、创世次序、词汇和叙事结构差异作了说明，同时强调将其分开研究不排除分析编订后的现存文本。来源：[TheTorah.com：Differing Conceptions of the Divine Creator](https://www.thetorah.com/article/differing-conceptions-of-the-divine-creator)

本次阶段 1 已生成这两组带原文跨度及学术来源的候选配置：经典 P/J? 划分；P + “非 P、J 归属未定/多传统材料”路径。两条记录均进入人工审阅队列，`confidence` 保持空值、`human_approved=false`；没有一组自动成为有效分层。`D` 标为“当前语料不适用”，没有指派给《创世记》。

**再次确认：**阶段 0 的结构性目标已达成；粒度字段、行切分和译本文本属于已披露的工程近似。本次阶段 1 只提出待审候选，没有作历史裁决。由于 D 典不在当前语料且两条候选未签字，Phase1 完整验收门槛尚未通过，Phase2 未启动。
